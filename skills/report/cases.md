# report 사례

보고서를 보고 받은 지적을 쌓은 문서임. `build-report.mjs`를 실행하기 전에 처음부터 끝까지 읽음.

- 사례 하나는 **지적 · 고치기 전 · 고친 뒤 · 지킬 것**으로 적음
- 예시는 회의실 예약 서비스로 통일함 (예약 칸 `A회의실 09:00`, 외부 공개, 이용료, 최소 인원)
- 새 지적을 받으면 맨 아래에 번호를 이어 붙임. 앞 사례를 지우거나 합치지 않음
- 형식 규칙은 `SKILL.md`의 `보고서 형식`에 있음. 이 문서의 `지킬 것`과 `SKILL.md`가 다르면 `SKILL.md`를 따름

## 1. 변경 전 · 후 비교 없이 테스트 결과만 있음

- **지적**: 테스트를 한 것만 있고, 이번 변경으로 기존에 어땠던 것이 어떻게 바뀌었는지가 안 드러남
- **고치기 전**: 절이 모두 "저장하면 DB에 들어감", "다른 화면에 반영됨" 같은 확인 결과뿐
- **고친 뒤**: 앞쪽에 변경사항 절(화면 · 설정 방법 · 표시)을 두고, 같은 데이터로 변경 전과 변경 후에서 같은 장면을 찍어 `compare`로 나란히 놓음
- **지킬 것**: `SKILL.md` 보고서 형식 5 · 5-1

## 2. 어떤 상황에서 무엇이 되어야 하는지 안 보임

- **지적**: "이러이러한 상황에서 이게 되어야 한다"가 명확히 전달되지 않음
- **고치기 전**: 결과만 적은 표 (`요청 | 대상 | 결과`), 캡처 설명에 결과만
- **고친 뒤**: 확인 절마다 상황과 결과를 함께 적은 표
- **지킬 것**: `SKILL.md` 보고서 형식 7 · 10 · 11

## 3. 결과 칸에 변경 전 → 변경 후를 화살표로 적음

- **지적**: 표 안에서도 변경 전 · 후를 따로 볼 수 있어야 함. 화살표 말고 칸으로 구분
- **고치기 전**: 결과 칸에 `변경 전: 체크 → 외부 공개 → 별도 창 → 변경 후: 칸에서 바로`, `고치기 전: 0원으로 공개됨 → 고친 뒤 비공개로 바뀜`
- **고친 뒤**: 맨 위를 `변경사항` 표(항목 | 변경 전 | 변경 후)와 `확인 결과` 표(확인 항목 | 되어야 하는 것 | 결과)로 나눔. 고치기 전 · 후는 그 절의 캡처로 보여 줌
- **지킬 것**: `SKILL.md` 보고서 형식 16 · 10

## 4. 결론 문장에 아래 절 번호를 넣음

- **지적**: 제목 바로 아래부터 "6번 9번이 뭐지?"를 생각하게 됨
- **고치기 전**: `lead` 끝에 `확인 중 찾은 문제 2개(6번 · 9번)는 고쳤음`
- **고친 뒤**: `lead`는 무엇을 바꿨는지만 적음. 고친 문제는 결과 표 해당 줄과 그 절에만 적음
- **지킬 것**: `SKILL.md` 보고서 형식 1 · 0-5

## 5. "변경 전 2단계" 같은 이상한 용어

- **지적**: "변경 전 2단계"는 무슨 말인지 모름
- **고치기 전**: 기존 방식의 두 번째 화면에 `변경 전 2단계`, 저장을 두 번 나눈 캡처에 `1차:` · `2차:`
- **고친 뒤**: `기존 방식: 별도로 뜨는 외부 공개 창`, 저장마다 한 일을 나타내는 이름
- **지킬 것**: `SKILL.md` 보고서 형식 15

## 6. 진행한 테스트 목록이 없음

- **지적**: 어떤 테스트들을 진행했는지 안 적혀 있음
- **고치기 전**: 확인 결과만 있고, 어떻게 확인했는지 · 자동 테스트는 무엇을 돌렸는지 없음
- **고친 뒤**: `env`에 `확인 방법` 줄(브라우저를 몇 개 무슨 역할로 띄웠는지, DB 조회 · API 호출로 봤는지), 마지막에 `자동 테스트` 절(종류 | 테스트 이름 | 결과)
- **지킬 것**: `SKILL.md` 보고서 형식 4 · 14

## 7. 넓고 낮은 캡처를 좌우로 놓아 글자를 못 읽음

- **지적**: 비교 캡처가 작아서 보기 힘듦
- **고치기 전**: 1720×230처럼 넓고 낮게 자른 캡처를 `compare`로 좌우에 놓음 → 절반 폭으로 줄어 글자가 안 읽힘
- **고친 뒤**: 그 비교에 `stack: true`를 줘서 위아래로 놓음
- **지킬 것**: `SKILL.md` 보고서 형식 6

## 8. 맨 위 결과 표와 아래 절이 하나씩 맞지 않음

- **지적**: 결과 표를 보고 아래에서 해당 절을 찾을 수 없음
- **고치기 전**: 결과 표 항목과 절 제목이 다르고, 결과 표의 한 줄이 여러 절에 걸침
- **고친 뒤**: 결과 표의 번호와 이름을 절 제목과 같게 하고, 한 줄 = 한 절
- **지킬 것**: `SKILL.md` 보고서 형식 3

## 9. 맨 위 표 이름을 "바뀐 것"으로 씀

- **지적**: "바뀐 것"보다 "변경사항"이라는 용어가 더 좋음
- **고치기 전**: 맨 위 표 · 절 이름이 `바뀐 것`
- **고친 뒤**: `변경사항`
- **지킬 것**: `SKILL.md` 보고서 형식 15

## 10. 맨 위 두 표의 번호가 이어짐

- **지적**: 각 표에서 순서는 독립적이어야 함
- **고치기 전**: `변경사항` 표가 1~3, `확인 결과` 표가 4~12로 번호가 이어짐
- **고친 뒤**: 두 표 모두 1부터 매김. 아래 절도 `part`로 묶음을 나누고, 묶음 안에서 표와 같은 번호를 씀
- **지킬 것**: `SKILL.md` 보고서 형식 2 · 3 · 0-5

## 11. 어떤 데이터로 무엇을 했는지 안 적힘

- **지적**: 어떤 데이터를 이렇게 바꿨더니 이렇게 됐다가 보여야 함. 길면 접어 둬도 되지만, 무엇을 했는지 · 테스트한 데이터가 무엇인지 알 수 있어야 함
- **고치기 전**: 절에 요약만 있고, 어느 칸을 어떤 값에서 어떤 값으로 바꿨는지, 어떤 요청을 보냈는지 없음
- **고친 뒤**: 절마다 접힌 상세(`details`)를 둠. 칸 · id · 저장된 값 · 한 일 · 저장 후 DB, 보낸 요청 본문과 응답, 남은 변경 기록, 정리한 데이터
- **지킬 것**: `SKILL.md` 보고서 형식 13

## 12. 요약을 한 문단으로 씀

- **지적**: 요약은 한 줄 한 줄 나눠 적어야 함. 줄마다 핵심만, 기존과 비교해서 결과적으로 뭘 했는지만 드러나면 됨
- **고치기 전**: `lead`가 `외부 공개 모드를 전용 표로 바꿈. 기존에는 칸을 체크하고 별도 창에서 설정했는데, 이제 표의 칸에서 바로 …` 한 문단
- **고친 뒤**: `lead`를 배열로 씀. 예: `공개 · 이용료 · 최소 인원을 별도 창 없이 표의 칸에서 바로 바꿈`, `이용료 칸을 비우면 0원으로 공개되지 않고 비공개가 됨`
- **지킬 것**: `SKILL.md` 보고서 형식 1

## 13. 요약에 세부 내용까지 적음

- **지적**: 표시 색 · 취소선, 빈 값 처리, 다른 화면 반영 같은 건 세부 내용임. 위에 세부까지 적으면 글이 더 안 읽힘
- **고치기 전**: `lead` 6줄 (큰 변경 2줄 + 세부 4줄)
- **고친 뒤**: 큰 변경 2줄만. 세부는 변경사항 표 · 확인 결과 절에만
- **지킬 것**: `SKILL.md` 보고서 형식 1

## 14. 조작을 줄임말로 적음

- **지적**: `Shift + 칸 누름 (A회의실 09:00~11:00)`이 무슨 말인지 모름
- **고치기 전**: `Shift + 칸 누름 (A회의실 09:00~11:00)`, `Shift 구간에 들어감`
- **고친 뒤**: `A회의실 09:00 칸을 누른 뒤, Shift 키를 누른 채 A회의실 11:00 칸을 누름`, 되어야 하는 것 `사이의 10:00까지 3개가 한 번에 공개됨`, 직접 누르지 않은 칸은 `직접 누르지 않음. 09:00과 11:00 사이라 같이 공개됨`
- **지킬 것**: `SKILL.md` 보고서 형식 12

## 15. 상황을 데이터 상태로만 적음

- **지적**: 상황을 `비공개 칸`처럼 두지 말고 `공개 칸을 비공개로 변경`처럼 명확하게 말해야 함
- **고치기 전**: `비공개 칸`, `공개 칸`, `key가 틀림`, `저장 직후`, `예약된 칸`
- **고친 뒤**: `비공개 칸을 공개로 변경`, `공개 칸을 비공개로 변경`, `공개 칸의 이용료 변경`, `틀린 API key로 조회`, `이미 예약된 칸(A회의실 10:00)에 다시 예약`
- **지킬 것**: `SKILL.md` 보고서 형식 8

## 16. 값 변경과 결과를 글로만 적음

- **지적**: 값 변경을 글로 적지 말고 칩과 화살표로 보여야 함. 결과도 값마다 확인됐다는 걸 분명히 보여야 함. 결과는 GREEN · RED로
- **고치기 전**: 한 일 칸 `A회의실 09:00을 3명 이상에서 4명 필수로, B회의실 10:00을 4명 필수에서 2명 이상으로`, 결과 칸 `4, 2로 저장` · `정상`
- **고친 뒤**: 데이터마다 한 줄(`대상` 열), 값은 `{ "from": "3명 이상", "to": "4명 필수" }` → 회색 칩 → 진한 칩, 결과는 `GREEN` · `RED` 배지. 같은 상황의 줄은 `null`로 상황 칸을 합침. 고치기 전 · 후는 `RED 고치기 전: …` / `GREEN 고친 뒤` 두 줄
- **지킬 것**: `SKILL.md` 보고서 형식 10 · 11

## 17. 한 표만 고치고 다른 표는 그대로 둠

- **지적**: 한 표에서만 열 구성이 바뀌고, 다른 표는 예전 구성 그대로임
- **고치기 전**: 확인 결과 1번 표만 `상황 | 대상 | 저장 후 DB | 결과`, 나머지는 `상황 | 되어야 하는 것 | 결과`
- **고친 뒤**: 모든 확인 결과 표를 `상황 | 대상 | 확인한 값 | 결과`로 맞춤
- **지킬 것**: 표시 방식을 바꾸면 보고서의 같은 종류 표를 모두 같이 바꿈. 형식 규칙은 `SKILL.md`에 둠

## 18. 대상을 개수 · 구간으로 줄여 적음

- **지적**: `처음 변경 7개`처럼 줄이지 말고 다 보여 줘야 함
- **고치기 전**: 대상 `처음 변경 7개`, 기록 표 `나머지 6개`, `A회의실 09:00~11:00`, 조회 응답 일부만
- **고친 뒤**: 칸마다 한 줄로 풀고, 조회 응답은 받은 응답 전체에서 칸마다 값을 옮겨 적음
- **지킬 것**: `SKILL.md` 보고서 형식 9. 확인할 때 받은 응답 · 기록은 나중에 풀어 적을 수 있게 전체를 남겨 둠

## 19. 독자가 확인 내용을 안다고 가정함

- **지적**: 각 테스트에서 무엇을 했는지 독자가 안다고 가정하지 말고, 전혀 모르는 상사에게 보고한다고 생각하고 적어야 함. 모든 항목에 걸친 것은 공통 영역에 적어야 함
- **고치기 전**: 테스트에서 붙인 이름과 화면 이름을 설명 없이 씀. 데이터 변경 내용은 확인 결과 1번 접힌 상세에만 있음. 절 첫 문장이 `확인한 값은 응답.`처럼 결과 위치만 적음
- **고친 뒤**: `확인 결과` 묶음 앞에 변경 표(대상마다 바꾼 값 칩과 목적), 모든 절 첫 문장을 목적 → 한 일 → 본 곳으로
- **지킬 것**: `SKILL.md` 보고서 형식 `독자` 0-1 ~ 0-3

## 20. 설명을 문단으로 써서 문장 중간에서 잘림

- **지적**: 설명 문단이 중간에서 잘림. `아래 절들은 한 번의 확인에서 나온 결과임`은 무슨 말인지
- **고치기 전**: 묶음 앞 설명과 절 설명을 문자열 문단으로 씀 → 한 줄 폭 제한 때문에 문장 중간에서 줄이 바뀜. 첫 문장은 읽어도 새로 아는 게 없음
- **고친 뒤**: `text`를 배열로 써서 목록으로 그림. 한 줄에 사실 하나(`목적:` · `데이터:` · `본 곳:`), 뜻 없는 문장은 뺌
- **지킬 것**: `SKILL.md` 보고서 형식 `독자` 0-3 · 0-4

## 21. 앞에서 뒤 절을 가리키고, 시간 순서 표를 만듦

- **지적**: 확인 순서 표는 빼도 됨. 위에 있는 섹션에서 아래에 나올 절을 가리키면 헷갈림
- **고치기 전**: `확인 순서` 표(시각 | 한 일 | 관련 절), 설명에 `(아래 변경 표)` · `확인 결과 1~5번은 …`, 목적 칸에 `(확인 결과 4번)`, 캡처 설명에 `(창은 아래)`
- **고친 뒤**: `확인 순서` 표를 빼고, 뒤를 가리키는 말을 모두 뺌
- **지킬 것**: `SKILL.md` 보고서 형식 `독자` 0-2 · 0-5

## 22. 여러 번 나눠 한 작업을 순번으로 부름

- **지적**: `1차 변경` · `2차 변경`보다 뭘 했는지를 나타내는 말로 바꿔야 함
- **고치기 전**: `1차 변경` · `2차 변경`
- **고친 뒤**: `처음 공개`(비공개였던 7개를 새로 공개) · `공개 뒤 수정`(공개된 상태에서 비공개 · 이용료 · 최소 인원 · 새로 공개 5건)
- **지킬 것**: `SKILL.md` 보고서 형식 `용어` 15

## 23. 보고서에서 정한 이름이 일반 글자와 구분되지 않음

- **지적**: `처음 공개` 같은 이름은 태그로 나타내서 이름임을 알 수 있게 해야 함
- **고치기 전**: 문장 속에 일반 글자로 섞여 있어서 이름인지 설명인지 구분이 안 됨
- **고친 뒤**: `[[이름]]`으로 감싸 검은 바탕 태그로 그림
- **지킬 것**: `SKILL.md` 보고서 형식 `용어` 15

## 24. 이름의 뜻을 보려면 용어 표까지 올라가야 함

- **지적**: 누르면 바로 뜻을 확인할 수 있어야 함. 이동하면 다시 찾아 내려오기 힘듦
- **고치기 전**: 이름 태그는 모양만 태그이고, 뜻은 맨 위 용어 표에만 있음
- **고친 뒤**: 태그를 누르면 태그 바로 아래에 뜻 상자가 뜸 (페이지 이동 없음, 다시 누르기 · 바깥 누르기 · Esc로 닫음). 뜻은 `terms`의 같은 이름 줄에서 가져옴
- **지킬 것**: `SKILL.md` 보고서 형식 `독자` 0-1

## 25. 용어 뜻을 줄줄이 문단으로 쓰고, 한 일을 흐리게 씀

- **지적**: 태그를 눌렀을 때 뜨는 뜻이 줄줄이 적혀 있음. `이번 확인에서` 같은 말은 필요 없고, 뭘 했는지 명확히 적어야 함
- **고치기 전**: `이번 확인에서 데이터를 바꾼 두 번째 저장. 처음 공개로 공개된 상태에서 A회의실 09:00 비공개로, …` 한 문단
- **고친 뒤**: `저장: 10/31 13:29:57` · `한 일: 공개 칸 1개를 비공개로, 최소 인원 2개 · 이용료 1개를 바꾸고, 비공개 칸 1개를 새로 공개` 두 줄 + `대상 | 바꾼 값` 표(값 칩)
- **지킬 것**: `SKILL.md` 보고서 형식 `독자` 0-1 · 0-4

## 26. 다 아는 용어까지 용어 표로 설명함

- **지적**: 업무에서 다 아는 용어는 굳이 안 써도 됨. 정리할 것은 테스트로 무엇을 했는지 간략히 적고, 그것을 상세하게 보여 주는 것
- **고치기 전**: 맨 위 `용어` 표에 업무 용어 · 화면 이름 · 탭 역할까지 12줄
- **고친 뒤**: 용어 표를 그리지 않음. 테스트에서 한 일 두 가지만 `확인 결과` 공통 영역에 한 줄 설명 + 상세 표로 두고, 태그를 누르면 그 뜻이 뜨게 `terms`에만 남김
- **지킬 것**: `SKILL.md` 보고서 형식 `독자` 0-1

## 27. API 응답의 코드 값을 뜻 없이 적음

- **지적**: `NORMAL`은 뭐고 `DISCOUNT`는 뭔지
- **고치기 전**: `95000 · MIN_4 · DISCOUNT`
- **고친 뒤**: `95,000 · 4명 필수(MIN_4) · 할인가(DISCOUNT)`. 할인가 · 정가는 응답을 만드는 코드에서 정하는 기준을 보고 적음
- **지킬 것**: `SKILL.md` 보고서 형식 10

## 28. 고친 동작을 핵심 상황이 아닌 데이터로 찍음

- **지적**: 비공개로 바뀌면 배경이 회색이 되는데, 두 번째 그림은 왜 안 되는지
- **고치기 전**: 이용료 칸 비우기의 고친 뒤 캡처를 원래 비공개였던 칸으로 찍음 → 저장된 값과 같아져서 흰색 · `변경 0건`으로 보임. 고친 동작의 핵심(저장된 공개 칸의 이용료를 비우면 비공개로)은 안 보임
- **고친 뒤**: 저장된 공개 칸의 이용료를 비운 캡처를 추가함 → 회색 · `변경 1건`. 기존 캡처 설명에는 흰색인 이유를 적음
- **지킬 것**: `SKILL.md` 보고서 형식 5-1
