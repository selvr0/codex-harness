# 주제 기록 (session-topics)

대화가 길어지면 앞에서 무엇을 이야기하고 정했는지 놓침. 그래서 주제마다 한 줄씩 과제 폴더의 `docs/topics.md`에 쌓음.

## 규칙

- **적는 때**: 주제가 바뀌었을 때, 또는 한 주제에서 결정이 나왔을 때
- **한 주제에 한 줄**: 주제 이름, 결론이나 결정, 이유
- **이미 있는 주제면 그 줄을 고침**: 같은 주제를 다시 이야기해서 결론이 바뀌었으면 새 줄을 만들지 않고 그 줄의 결론을 바꿈. 바뀐 사실은 `(10:42 변경: 이전 결론 → 새 결론)`으로 남김
- **지금 이야기 중인 주제**: 번호 앞에 `▶`를 붙임. `▶`는 하나만 둠
- **사실만 적음**: 확인한 것과 합의한 것만. 추측은 적지 않음
- 실무자 에이전트와의 대화에서 알게 된 것도 주제로 적음 (예: `실무자: 저장 기준`)

## 파일 모양

```markdown
# 주제

| # | 주제 | 결론 · 결정 | 이유 |
|---|---|---|---|
| 1 | 실무자: 누가 쓰는지 | 선수 본인이 혼자 연습할 때 씀 | 코치가 일정상 매번 함께할 수 없음 |
| 2 | 저장 방식 | 서버에 저장 | 여러 기기에서 다시 들어야 함 |
| ▶3 | 화면 구성 | 질문 → 녹음 → 다시 듣기 한 화면 | 실무자 확인 (10:30) |
```

## 자동 요약 (사용자가 "주제 정리해" 할 때만)

직접 적다가 빠진 게 많거나, 대화 전체를 한 번에 다시 정리하고 싶을 때 씀. 세션 기록을 읽어 다른 Codex 실행(`codex exec`)에 요약을 맡기고 `docs/topics.md`를 새로 씀.

```bash
# 과제 폴더에서, 지금 Codex 가 돌고 있는 터미널과 다른 탭에서 실행
node <이 스킬 폴더>/scripts/summarize-topics.mjs
node <이 스킬 폴더>/scripts/summarize-topics.mjs --model <가벼운 모델>   # 모델 지정
node <이 스킬 폴더>/scripts/summarize-topics.mjs --dry-run               # 넘길 대화만 보기
```

- **세션 찾기**: `~/.codex/sessions/` 에서 작업 폴더가 지금 폴더인 세션 중 가장 최근 것을 읽음. 메시지마다 앞 600자, 최근 400개까지 넘김. Codex 가 자동으로 넣는 지침 · 환경 블록은 뺌
- **요약 실행**: `codex exec --ephemeral -s read-only` 로 돌림. 요약 실행 자체는 세션 기록을 남기지 않고, 명령을 실행하지 못함
- **기존 파일 유지**: 기존 `docs/topics.md` 를 같이 넘겨 번호와 주제 이름을 최대한 유지함. 결과가 형식(`# 주제`로 시작)과 다르면 파일을 고치지 않음
- **비용**: 한 번에 약 1만 5천 토큰, 5초 정도 (짧은 대화 기준). 토큰 사용량이 평가에 참고되므로 매 턴 돌리지 않음
- **다른 탭에서 돌리는 이유**: Codex 안에서 돌리면 네트워크 사용 승인을 물어봄

## 쓰는 곳

- 진행 중에는 사용자가 에디터 탭으로 열어 둠
- **후속 서술형(AI 사용 불가) 전에 이 파일을 다시 읽음.** 무엇을 왜 정했는지 복기하는 자료임
- 에디터 탭이 파일 변경을 바로 다시 읽지 않으면, 사용자는 탭을 다시 열어 확인함
